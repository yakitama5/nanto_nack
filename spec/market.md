# 📦 フリマアプリ謎解き（全4ステージ）実装計画書

## 1. 概要と要件（※厳守事項）
スマホの直感操作をテーマにした謎解きゲームの「フリマアプリ（メルカリ系）編」を実装する。
UIの実装には、いいねのアニメーション用に **`like_button`** パッケージを使用する。

**【Presentation層の共通化に関する厳守事項】**
全4問（Quiz1〜4）は独立したクイズとして出題されるが、Presentation層（モックのフリマUIと状態管理）は**全クイズで完全に共通の基盤（1つの大きなアプリ）**を使用することを厳守する。
クイズごとに機能を制限せず、常にすべての機能（画像のスワイプ、いいねの切り替え、出品者タップ、購入ボタンのタップ）が動作する状態を維持すること。
クイズによって変化するのは、**「ユーザーのどの操作・状態変化を監視してクリア判定（正解）とするか」という条件のみ**である。

## 2. データモデル
以下のクラスを定義して、商品データを表現する。

### FleaMarketItem
- `id`: String (商品ID)
- `title`: String (商品名)
- `price`: int (価格)
- `imageUrls`: List<String> (商品画像のURLリスト。表、横、裏などの複数枚)
- `description`: String (商品説明文)
- `sellerName`: String (出品者名)
- `sellerRating`: double (出品者の星評価。例: 4.8)

## 3. 状態管理 (Riverpod)
フリマアプリの共通状態を管理する `FleaMarketNotifier` を実装する。クイズごとに初期化されるよう `autoDispose` を使用すること。

### 保持する状態 (State)
- `item`: FleaMarketItem (表示中の商品データ。Quiz開始時にモックデータを注入)
- `currentImageIndex`: int (現在表示されている画像のインデックス。初期値は0)
- `isLiked`: bool (「いいね」されているかどうか。初期値はfalse)

### 状態更新メソッド (Actions)
- `updateImageIndex(int index)`: 画像がスワイプされた際にインデックスを更新する。
- `toggleLike()`: `isLiked` の状態を反転させる。
- `tapSellerProfile()`: 出品者情報がタップされたことを記録・判定用。
- `tapBuyButton()`: 購入ボタンがタップされたことを記録・判定用。

## 4. 共通UIコンポーネント構成
本物のフリマアプリを模倣し、購買意欲を高めるUIで構築する。

- **FleaMarketScaffold**: 全体のベース。
  - **重要**: `Scaffold` の `bottomNavigationBar` （または `Stack` による最前面下部固定）を利用し、画面幅いっぱいの目立つ色（赤など）で**「購入手続きへ」ボタン**を常駐させる。タップで `tapBuyButton` を発火。
- **ItemScrollView**: メインのスクロール領域（`SingleChildScrollView` 等）。
  - **ImageCarouselArea**: 画面最上部の商品画像エリア。
    - `PageView` を使用して画像を横スワイプ可能にする。ページ切り替え時に `updateImageIndex` を発火させる。
    - 画像のすぐ下に `smooth_page_indicator` パッケージ（またはカスタムUI）を用いて、**ドットインジケーター**を配置し、現在の画像位置を視覚的に示す。
  - **ItemHeaderInfo**: 商品名と価格の表示エリア。
    - 右端などにハートマークの「いいね」ボタンを配置する。
    - **重要**: ここに **`like_button`** パッケージの `LikeButton` ウィジェットを使用すること。タップ時に弾けるようなアニメーションを表示させ、`onTap` コールバック内で `toggleLike()` を発火させる。
  - **SellerInfoRow**: スクロールした先にある出品者情報エリア。
    - 丸いアイコン、名前、星評価を横並びに配置。全体を `InkWell` や `GestureDetector` でラップし、タップ時に `tapSellerProfile` を発火させる。

## 5. クイズごとのクリア判定条件
ベースとなるアプリは常にフル機能で動作する。

### Quiz1: 商品の「裏面」の写真を確認する
- **お題**: 「裏側に傷がないか気になるな。最後の写真までスワイプして確認しよう」
- **想定操作**: 画像下の「・・・（ドット）」インジケーターを頼りに、商品画像を左へ数回スワイプする。
- **クリア条件**: `updateImageIndex()` が呼ばれ、`currentImageIndex` が `imageUrls.length - 1`（最後の画像）になった瞬間にクリア。

### Quiz2: とりあえずキープ（お気に入り）する
- **お題**: 「後で比較したいから、とりあえず『いいね』して保存しておこう」
- **想定操作**: 画面右下、または商品名付近にある「ハートマーク」をタップする。
- **クリア条件**: `toggleLike()` が実行され、`isLiked` が `true` になった瞬間にクリア。

### Quiz3: 出品者のプロフィールを見に行く
- **お題**: 「この出品者、信頼できる人かな？プロフィールと評価を見に行こう」
- **想定操作**: 画面を下の方までスクロールし、出品者情報の行（アイコンや星があるエリア）をタップする。
- **クリア条件**: `tapSellerProfile()` が呼び出された瞬間にクリア。

### Quiz4: 商品を購入する
- **お題**: 「よし、これに決めた！購入手続きに進もう」
- **想定操作**: 画面の最下部に常に固定されている「購入」ボタンをタップする。
- **クリア条件**: `tapBuyButton()` が呼び出された瞬間にクリア。
